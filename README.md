# Task Manager API

A secure REST API for managing user tasks with **Spring Boot**, **Spring Security**, **JWT authentication**, and **MySQL**.  
The project uses **Docker Compose** to run both the Spring Boot application and MySQL database – no local Java or MySQL installation required.

## Features

- User registration & login with JWT
- Role‑based access (USER / ADMIN)
- Task CRUD operations (create, read, update, delete)
- Input validation & global exception handling
- MySQL database with automatic table creation
- Fully containerised with Docker

## Technologies

- Java 21
- Spring Boot 3.5.14
- Spring Security 6
- JWT (JJWT)
- Spring Data JPA (Hibernate)
- MySQL 8
- Maven
- Docker & Docker Compose

## Getting Started

### Prerequisites

- **Docker** and **Docker Compose** installed on your machine  
  (Download from [docker.com](https://docker.com))

### 1. Clone the repository

```bash
git clone https://github.com/Naveen02627/task-manager-api.git
cd task-manager-api
Note: Replace task-manager-api with the actual name of your repository if different.

2. Run with Docker Compose
The project includes a Dockerfile and docker-compose.yml.
Start the entire stack (MySQL + Spring Boot app) with one command:

bash
docker-compose up --build
The Spring Boot application will start on http://localhost:8080

MySQL runs on port 3307 (mapped internally to container port 3306)

The database taskdb is automatically created and tables are generated by Hibernate (ddl-auto=update)

Note: The first build may take a few minutes because Maven downloads dependencies and Docker builds the image.

3. Verify the application is running
Open another terminal and run a health check:

bash
curl http://localhost:8080/auth/login -X POST -H "Content-Type: application/json" -d '{"email":"dummy","password":"dummy"}'
You should receive a 404 or 401 response – that’s fine because the endpoint expects real credentials.
It confirms the application is reachable.

API Endpoints & Testing
All endpoints are tested with cURL commands.
You can also use Postman or any API client.

Important:

Public endpoints (/user/register, /auth/login) must not include an Authorization header.

All other endpoints require a valid JWT token in the header:
Authorization: Bearer <your-token>

1. Register a new user (public)
bash
curl -X POST http://localhost:8080/user/register \
  -H "Content-Type: application/json" \
  -d '{
    "name": "John Doe",
    "email": "john@example.com",
    "password": "secret123",
    "role": "USER"
  }'
Expected response (201 Created):

json
{
  "id": 1,
  "name": "John Doe",
  "email": "john@example.com",
  "role": "USER"
}
![Registration Response](screenshots/register.png)

2. Login and get JWT token (public)
bash
curl -X POST http://localhost:8080/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "john@example.com",
    "password": "secret123"
  }'
Response (200 OK):

json
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "type": "Bearer",
  "userId": 1,
  "email": "john@example.com"
}
Save the token value – you will use it in all subsequent requests.


![login response with token](screenshots/register.png)

3. Get user by ID (authenticated)
Replace <your-token> with the token from step 2.

bash
curl -X GET "http://localhost:8080/user/getUser?id=1" \
  -H "Authorization: Bearer <your-token>"
Response (200 OK):

json
{
  "id": 1,
  "name": "John Doe",
  "email": "john@example.com",
  "role": "USER"
}

![user profile](screenshots/register.png)

4. Add a task (authenticated)
bash
curl -X POST http://localhost:8080/task/add \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-token>" \
  -d '{"task": "Buy groceries"}'
Response (201 Created):

json
{
  "id": 1,
  "task": "Buy groceries",
  "user": {
    "id": 1,
    "name": "John Doe",
    "email": "john@example.com"
  }
}

![task created](screenshots/register.png)

5. Get all tasks of the authenticated user
bash
curl -X GET http://localhost:8080/task/getAll \
  -H "Authorization: Bearer <your-token>"
Response (200 OK):

json
[
  {
    "id": 1,
    "task": "Buy groceries",
    "user": { ... }
  }
]

![list of tasks](screenshots/register.png)

6. Update a task
Replace 1 with the actual task ID.

bash
curl -X PUT http://localhost:8080/task/update/1 \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-token>" \
  -d '{"task": "Buy organic groceries and cook dinner"}'
Response (200 OK): Updated task object.

7. Delete a task
bash
curl -X DELETE http://localhost:8080/task/delete/1 \
  -H "Authorization: Bearer <your-token>"
Response (200 OK): The deleted task object.

8. Admin only – get all users
First, register an admin user:

bash
curl -X POST http://localhost:8080/user/register \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Admin",
    "email": "admin@example.com",
    "password": "admin123",
    "role": "ADMIN"
  }'
Login as admin to obtain an admin token, then:

bash
curl -X GET http://localhost:8080/user/all \
  -H "Authorization: Bearer <admin-token>"
Response (200 OK): Array of all users (passwords omitted).

Manual Setup (without Docker)
If you prefer to run the application without Docker, you need:

Java 21 (JDK)

MySQL 8 installed locally

Maven (or use the Maven wrapper)

Steps
Create a MySQL database named taskdb:

sql
CREATE DATABASE taskdb;
Update src/main/resources/application.properties with your MySQL credentials:

properties
spring.datasource.url=jdbc:mysql://localhost:3306/taskdb?createDatabaseIfNotExist=true
spring.datasource.username=root
spring.datasource.password=your_password
Build and run the application:

bash
mvn clean package
java -jar target/Anything-0.0.1-SNAPSHOT.jar
The application will be available at http://localhost:8080.

Troubleshooting
JWT SignatureException
Cause: You are using an old token generated before the application was restarted.

Fix: Login again to obtain a fresh token (POST /auth/login). Remove any Authorization header when calling /user/register or /auth/login.

Connection refused / MySQL not reachable
Wait a few seconds after docker-compose up – MySQL takes time to initialise.

If you manually changed the MySQL port, ensure the SPRING_DATASOURCE_URL in docker-compose matches.

Database not created
The URL includes ?createDatabaseIfNotExist=true – it works for MySQL.

If you still get "Unknown database", create the database manually:

bash
docker exec -it taskdb-mysql mysql -u root -p
CREATE DATABASE taskdb;
